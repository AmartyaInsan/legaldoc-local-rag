# Plan 2: BYO Retrieval & Conversation Memory

**Complexity**: ⚠️ **Medium** (Full RAG Pipeline: Ingestion UI + Text Chunking + Ollama `nomic-embed-text` Embeddings + pgvector / Vector Store + Retrieval Tool + Stateless History)

## Objective
Build Module 2 according to PRD.md:
1. Transition from managed black-box RAG to **custom retrieval** (BYO Retrieval).
2. Document ingestion pipeline: manual drag-and-drop upload, chunking, embedding generation using local Ollama (`nomic-embed-text:latest` 768-dim), and vector storage.
3. Vector similarity search via Supabase pgvector (`match_chunks`) with local fallback.
4. Retrieval tool / context injection into chat completions with Ollama (`qwen2.5:7b`).
5. Stateless conversation memory management: store and send chat history in Supabase.
6. Ingestion UI in frontend with tab switching (Chat & Documents).

---

## Tasks

### Task 1: Chunking and Embedding Service (Backend)
- **Description**:
  - Implement `backend/app/services/chunking.py` for text segmentation (sliding window, configurable chunk size ~600 chars, overlap ~100 chars, boundary-aware).
  - Implement `backend/app/services/embeddings.py` to call local Ollama (`http://localhost:11434/api/embeddings`) with model `nomic-embed-text:latest`, returning 768-dimensional float vectors. Support single and batch embeddings.
- **Validation**:
  - Unit test script verifying text chunking splits text properly and Ollama returns 768-dim vectors.

### Task 2: Vector Storage and Retrieval Service (Backend)
- **Description**:
  - Implement `backend/app/services/retrieval.py`.
  - Provide functions:
    - `store_document_chunks(document_id, user_id, chunks, embeddings)`: insert into Supabase `document_chunks` table (with in-memory vector store fallback).
    - `retrieve_relevant_chunks(query, user_id, top_k=5, threshold=0.3)`: generate query embedding with `nomic-embed-text`, call `match_chunks` RPC function in Supabase (or compute cosine similarity), and return sorted list of relevant chunks with score and metadata.
    - `format_rag_context(chunks)`: format retrieved chunks into an LLM context block with document source citations.
- **Validation**:
  - Test storing test chunks and performing a vector search query to verify relevant chunks are retrieved with accurate similarity scores.

### Task 3: Document Ingestion API Endpoints (Backend)
- **Description**:
  - Implement `backend/app/api/endpoints/documents.py`:
    - `POST /api/documents/upload`: Accept `multipart/form-data` file, extract text content (supports `.txt`, `.md`, `.json`, `.csv`), compute hash, save document record to `documents` table, run chunking + embedding, store chunks in `document_chunks`, update status to `completed`.
    - `GET /api/documents`: List documents for user with chunk count and status.
    - `DELETE /api/documents/{id}`: Remove document and cascade delete chunks.
  - Register router in `backend/app/main.py`.
- **Validation**:
  - Upload a test file via curl / python script, verify status is `completed`, and verify chunks are saved.

### Task 4: Integrate Retrieval and Stateless Memory into Chat (Backend)
- **Description**:
  - Update `backend/app/api/endpoints/chat.py`:
    - When user sends a message, query `retrieval_service.retrieve_relevant_chunks(user_message)` for relevant context.
    - If relevant chunks exist, prepend a structured system context containing the retrieved knowledge and instruct the model to cite sources.
    - Persist user message and completed assistant response to `messages` table in Supabase.
    - Return retrieved chunk sources in the SSE stream metadata or initial SSE event so the frontend can display citations.
- **Validation**:
  - Send a prompt referencing uploaded document content via SSE stream and verify response cites the document content accurately.

### Task 5: Frontend Ingestion UI & Tab Navigation
- **Description**:
  - Create `frontend/src/components/DocumentManager.tsx`:
    - Drag-and-drop file upload zone.
    - Document table with filename, size, chunk count, status badge (`completed`, `processing`, `failed`), and delete button.
  - Update `frontend/src/components/Header.tsx` to add view tabs: **Chat** and **Documents** (with document count badge).
  - Update `frontend/src/services/api.ts` with `fetchDocuments`, `uploadDocument`, `deleteDocument`.
  - Update `frontend/src/components/ChatMessage.tsx` to render retrieved sources / citations if available.
  - Update `frontend/src/App.tsx` to toggle between Chat and Document Manager views.
- **Validation**:
  - Run `npm run build` to verify clean TypeScript compilation and test document upload & view switching in UI.

### Task 6: End-to-End Validation & Progress Tracking
- **Description**:
  - Upload a sample knowledge document (e.g. `antigravity_rag_guide.md`).
  - Ask a question in Chat that relies on that knowledge document.
  - Verify Ollama `qwen2.5:7b` answers using the retrieved context from `nomic-embed-text:latest`.
  - Update `PROGRESS.md` for Module 2.
- **Validation**:
  - Complete prompt-to-retrieval-to-stream cycle successfully verified.
