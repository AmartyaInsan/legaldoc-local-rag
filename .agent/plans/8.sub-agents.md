# Plan 8: Sub-Agents (Deep Analysis Scenarios & Isolated Agent Spawning)

**Complexity**: ⚠️ **High** (Deep Scenario Detector + Isolated Sub-Agent Engine + Full-Document Sequential Reader + Hierarchical Reasoning Stream + UI Nested Agent Display)

## Objective
Implement Module 8 according to PRD.md:
1. **Detection of Full-Document Deep Analysis Scenarios**:
   - Intelligent detector identifying queries requiring whole-document synthesis, comprehensive audits, multi-document comparisons, or exhaustive extraction.
   - Distinguishes standard chunk-level RAG from holistic document-level analysis.
2. **Isolated Sub-Agent Spawning with Dedicated Tools**:
   - Main Coordinator Agent spawns isolated sub-agents (`DocumentAnalystSubAgent`, `ComparisonSubAgent`).
   - Dedicated tools:
     - `read_document_outline(document_id)`: Analyzes document schema, length, and sections.
     - `read_all_chunks_ordered(document_id)`: Sequential full-document reader (chunks 0..N) bypassing truncation.
     - `extract_deep_aspects(chunks, aspects)`: Multi-aspect extractor (Executive Summary, Key Findings, Risks, Methodology, Action Items).
     - `compare_documents(doc1_chunks, doc2_chunks)`: Cross-document comparative synthesis.
   - Sub-agent operates in an isolated prompt context to avoid context pollution and token overflow.
3. **Dual Agent Reasoning & Nested Tool Call Stream**:
   - Real-time streaming of both Main Agent delegation reasoning and Sub-Agent execution steps via SSE (`subagent_events`).
   - Captures timeline steps (Inspection -> Sequential Reading -> Aspect Extraction -> Synthesis).
4. **Hierarchical UI Agent Display**:
   - Interactive Sub-Agent panel in `ChatMessage.tsx` displaying agent badge, delegation rationale, execution timeline, and intermediate findings.
   - `ChatInput.tsx` quick triggers for Deep Analysis.
   - Message persistence in Supabase & memory with sub-agent metadata.

## Status: ✅ Completed

### Implementation Summary
1. **Scenario Detection & Identification (`backend/app/services/subagents/orchestrator.py`)**:
   - Accurately detects `deep_analysis` (single document holistic audit) and `comparative_analysis` (cross-document comparison matrix).
   - Intelligently binds target documents by filename matching, title tokens, or active metadata filter.
   - Preserves standard routes (Text-to-SQL, Web Search, Local Hybrid RAG) when deep analysis is not requested.

2. **Specialized Isolated Sub-Agents (`backend/app/services/subagents/`)**:
   - `DocumentAnalystSubAgent` (`analyst.py`): Performs full chronological reading (chunks 0..N) bypassing vector truncation, extracts 5 analytical pillars (Executive Overview, Key Findings, Risks, Operational Strengths, Action Items), and builds an execution trace.
   - `DocumentComparatorSubAgent` (`comparator.py`): Reads two documents in parallel/isolated passes and constructs a structured Markdown comparison matrix.
   - `llm_service.complete`: Provides dedicated non-streaming sub-agent prompt execution in isolated context windows.

3. **Multi-Agent Streaming & Message Persistence (`backend/app/api/endpoints/chat.py` & `router.py`)**:
   - `AgentRouter` invokes sub-agents when scenarios are detected and provides enriched audit context to the Main Agent.
   - Streams `subagent_events` over Server-Sent Events (SSE) in `/api/chat/stream`.
   - Persists `subagent_events` in message metadata (Supabase & local cache) for conversation thread rehydration.

4. **Frontend Hierarchical Reasoning UI**:
   - Enhanced `ChatMessage.tsx` with a collapsible, violet-themed Sub-Agent Reasoning Card displaying:
     - Sub-Agent avatar, name, role, execution status, and elapsed time.
     - Main Agent delegation rationale.
     - Live execution step timeline (Outline -> Sequential Read -> Aspect Extraction -> Synthesis).
     - Sub-agent findings summary banner.
   - Enhanced `ChatInput.tsx` with quick suggestion chips (`📊 Analisis Menyeluruh Dokumen`, `📑 Bandingkan Dokumen`) and capability badge (`🛠️ Tools: RAG • SQL • Web • 🤖 Sub-Agents`).
   - Integrated `onSubAgentEvents` in `frontend/src/services/api.ts` and `frontend/src/App.tsx`.
