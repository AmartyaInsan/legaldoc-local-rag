# Plan 5: Multi-Format Support & Cascade Deletes

**Complexity**: ⚠️ **Medium** (Docling Integration + HTML Parser + Multi-Format Support + Database & Memory Cascade Deletes + UI Filter Invalidation)

## Objective
Implement Module 5 according to PRD.md:
1. **Multi-Format Support**:
   - Add deep parsing for `.html` and `.htm` files using HTML text extraction (stripping scripts/styles, converting headings/paragraphs/tables to clean markdown/text).
   - Integrate optional IBM `docling` (`DocumentConverter`) for rich document parsing (PDF, DOCX, HTML) with graceful zero-dependency fallbacks (`pypdf`, native `.docx` XML extractor, `html.parser`).
   - Accept `.html`, `.htm`, `.pdf`, `.docx`, `.txt`, `.md`, `.csv`, `.json` seamlessly in the ingestion pipeline.
2. **Cascade Deletes**:
   - Ensure deleting a document purges all related chunks and vector embeddings from both Supabase (`document_chunks` table with `ON DELETE CASCADE`) and the local in-memory vector store cache (`_local_chunks`).
   - Ensure the frontend invalidates and resets any active retrieval filter targeting a deleted document to avoid orphan query scoping.
   - Add delete confirmation and visual feedback in `DocumentManager.tsx`.

## Tasks

### Task 1: HTML Deep Parsing & Docling Integration in `document_parser.py`
- **Description**:
  - Implement `extract_text_from_html(content_bytes: bytes) -> str` using `BeautifulSoup` (if installed) or Python's standard library `html.parser` to clean scripts, styles, and format readable text.
  - Implement `try_docling_parse(filename: str, content_bytes: bytes) -> Optional[str]` to leverage Docling if installed, returning structured markdown.
  - Update `parse_document(filename, content_bytes)` to handle `.html` and `.htm`, in addition to `.pdf`, `.docx`, `.txt`, `.md`, `.csv`, `.json`.
- **Validation**:
  - Test parsing a sample HTML snippet and verify text/headings are extracted cleanly without `<script>` or `<style>` artifacts.

### Task 2: Cascade Deletes in Backend API & Database Schema
- **Description**:
  - In `backend/app/api/endpoints/documents.py`:
    - Ensure `DELETE /api/documents/{document_id}` deletes all corresponding chunks from both `retrieval_service` local memory and Supabase `document_chunks`.
    - Return the deleted chunk count in the response payload.
  - In `backend/app/services/retrieval.py`:
    - Ensure `delete_document_chunks` returns the number of chunks purged.
  - In `backend/supabase_schema.sql`:
    - Verify `ON DELETE CASCADE` constraint on `document_chunks.document_id`.
- **Validation**:
  - Delete a document and verify neither the document nor any of its chunks remain in the vector index or database.

### Task 3: Frontend Ingestion & Cascade Delete UX
- **Description**:
  - In `frontend/src/components/DocumentManager.tsx`:
    - Add `.html` and `.htm` to file input `accept` attribute and dropzone instructions.
    - Add HTML file icon (`FileCode` / `Globe`).
    - Add delete confirmation dialog/toast so users don't accidentally remove documents.
  - In `frontend/src/App.tsx`:
    - When `handleDeleteDoc(id)` is triggered, check if `metadataFilter?.document_id === id`. If so, reset `metadataFilter` to `null`.
- **Validation**:
  - Select a document filter in Chat, delete that document in Knowledge Base, verify chat filter resets to "All Docs".
