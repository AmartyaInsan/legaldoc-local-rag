# Plan 4: Metadata Extraction & Filtered Retrieval

**Complexity**: ⚠️ **Medium** (LLM Structured Extraction + Pydantic Schema + Metadata Storage in Postgres + Filtered Vector Retrieval + UI Metadata Badges & Query Scoping)

## Objective
Implement Module 4 according to PRD.md:
1. **LLM-Based Structured Extraction**:
   - Use local Ollama (`qwen2.5:7b`) to analyze incoming documents and extract structured metadata: `title`, `summary`, `document_type`, `keywords`, and `language`.
   - Validate LLM extraction with strict Pydantic schemas.
2. **Metadata Storage**:
   - Persist document-level metadata in Supabase `documents` table (and memory cache).
   - Propagate document metadata (`doc_title`, `doc_type`, `keywords`) into every chunk in `document_chunks.metadata`.
3. **Filtered Vector Retrieval**:
   - Enhance `retrieval_service.retrieve_relevant_chunks` with `metadata_filter` (support filtering by `document_type`, `document_id`, or `keywords`).
   - Enhance Supabase schema with `match_chunks_filtered` RPC and local cosine similarity filtering.
4. **Chat & UI Integration**:
   - In `DocumentManager.tsx`: Display extracted title, summary, keyword tags, and document type badge.
   - In Chat view: Allow query scoping / filtering by specific document or document type.
   - Show enriched metadata in cited sources cards in chat.

## Tasks

### Task 1: Pydantic Schema & LLM Metadata Extraction Service
- **Description**:
  - Implement `backend/app/services/metadata_extractor.py`.
  - Define `ExtractedMetadata` Pydantic model (`title`, `summary`, `document_type`, `keywords`, `language`).
  - Use `AsyncOpenAI` client pointed to local Ollama (`qwen2.5:7b`) with `response_format={"type": "json_object"}` to parse the beginning of each uploaded document.
  - Provide fallback default metadata if LLM extraction takes too long or fails.
- **Validation**:
  - Test extractor on sample text and verify returned Pydantic object has title, summary, keywords, and type.

### Task 2: Metadata Storage & Chunk Enrichment
- **Description**:
  - Update `backend/app/api/endpoints/documents.py`:
    - After document parsing, call `metadata_extractor.extract_metadata(filename, text_content)`.
    - Save metadata in `documents` table and pass to `retrieval_service.store_document_chunks`.
    - Enrich each chunk's `metadata` dictionary with `doc_title`, `doc_type`, and `keywords`.
  - Update `backend/supabase_schema.sql` to include `metadata` column on `documents` and add `match_chunks_filtered` RPC.
- **Validation**:
  - Upload a document and verify returned document response contains extracted `metadata` (title, summary, keywords).

### Task 3: Filtered Vector Retrieval Service
- **Description**:
  - Update `backend/app/services/retrieval.py` to accept `metadata_filter: Optional[Dict[str, Any]] = None`.
  - Filter candidates before/after similarity ranking based on `document_id` or `document_type`.
  - Update `backend/app/schemas/chat.py` to accept optional `metadata_filter` in `ChatRequest`.
  - Update `backend/app/api/endpoints/chat.py` to pass the filter into retrieval.
- **Validation**:
  - Test retrieval with and without a filter, verifying only matching documents/chunks are retrieved when filter is applied.

### Task 4: Frontend UI Enhancements for Metadata
- **Description**:
  - Update `frontend/src/types/chat.ts` to include `metadata?: ExtractedMetadata` on `DocumentItem` and `metadata_filter` on `ChatRequest`.
  - Update `frontend/src/components/DocumentManager.tsx` to display summary, document type badge, and keyword chips for each document.
  - In `frontend/src/components/ChatInput.tsx` & `frontend/src/App.tsx`: Add a document filter selector (scope questions to a specific document or All Documents).
  - Update `frontend/src/components/ChatMessage.tsx` to display document type and keywords in cited sources.
- **Validation**:
  - Verify UI builds cleanly with `npm run build`.

### Task 5: Progress Tracking
- **Description**:
  - Update `PROGRESS.md` marking Module 4 completed.
