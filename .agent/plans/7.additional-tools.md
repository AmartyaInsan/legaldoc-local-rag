# Plan 7: Additional Tools (Text-to-SQL & Web Search Fallback)

**Complexity**: ⚠️ **Medium** (Text-to-SQL Engine + SQLite/Postgres Tabular Ingestion + DuckDuckGo Web Search Fallback + Multi-Tool Router + UI Tool Execution Badges & Web Citations)

## Objective
Implement Module 7 according to PRD.md:
1. **Text-to-SQL Tool**:
   - Query structured data: metadata of uploaded documents, chunks, and tabular data from uploaded CSV/JSON files.
   - Translate natural language questions into safe, read-only SQL queries (`SELECT` only, blocking dangerous mutations).
   - Execute queries against local SQLite database (mirroring knowledge base & CSV tables) and Supabase Postgres.
2. **Web Search Fallback Tool**:
   - Resilient, zero-config web search using DuckDuckGo via HTTP (no API key required, with optional Brave/Serper override).
   - Fallback trigger: Activated when local RAG retrieval similarity is low (< threshold) or when user query seeks external real-time knowledge.
   - Return web search citations with clickable external URLs and snippets.
3. **Multi-Tool Routing & SSE Attribution**:
   - Multi-tool router that analyzes user query intent and dispatches `local_retrieval`, `text_to_sql`, or `web_search`.
   - Real-time tool execution events streamed over SSE (`tool_start`, `tool_result`).
   - Unified citation attribution for both document chunks and web URLs.
4. **Enhanced UI**:
   - Tool execution status chips in `ChatMessage.tsx` (showing SQL executed, rows returned, web search terms, and web links).
   - Tool mode indicator in `ChatInput.tsx`.
   - Update `PROGRESS.md` upon completion.

## Tasks

### Task 1: Text-to-SQL Service & Dynamic Tabular Store
- **Description**:
  - Implement `backend/app/services/tools/text_to_sql.py`.
  - Maintain an in-memory SQLite database populated with `documents`, `document_chunks`, and dynamic tables from uploaded `.csv` files.
  - LLM prompt generates standard SQL from schema definition.
  - Strict SQL validator blocks `DROP`, `DELETE`, `UPDATE`, `INSERT`, `ALTER`, `TRUNCATE`.
  - Formats tabular results as Markdown tables and structured data.
- **Validation**:
  - Query "how many documents are in the knowledge base?" or "what is the largest file?" and verify SQL generation and accurate execution.

### Task 2: Web Search Fallback Service
- **Description**:
  - Implement `backend/app/services/tools/web_search.py`.
  - Zero-config DuckDuckGo HTML / instant API search via `httpx`.
  - Extracts title, snippet, and source URL for top 3-5 results.
  - Returns clean structured web citations.
- **Validation**:
  - Test query for external facts (e.g. "what is the latest release of Ollama?") and verify search results returned.

### Task 3: Multi-Tool Router & Agent Orchestration
- **Description**:
  - Implement `backend/app/services/tools/router.py`.
  - Determines which tool(s) to activate:
    - If quantitative / metadata / table question &rarr; `text_to_sql`.
    - If local knowledge query &rarr; `local_retrieval`.
    - If local retrieval returns 0 results or similarity < threshold (or user asks external info) &rarr; `web_search`.
  - Update `_generate_rag_stream` in `backend/app/api/endpoints/chat.py` to stream tool events and inject tool contexts into LLM prompt.
- **Validation**:
  - Verify SSE emits `tool_call` events and LLM synthesizes answer incorporating tool results.

### Task 4: Frontend UI Enhancements for Multi-Tool Attribution
- **Description**:
  - Update `frontend/src/types/chat.ts` to support tool events and web citations (`url`, `tool_used`).
  - Update `frontend/src/components/ChatMessage.tsx` to render tool execution pills (`📊 Text-to-SQL`, `🌐 Web Search`) and clickable web source links.
  - Update `frontend/src/components/ChatInput.tsx` to display active tools.
- **Validation**:
  - Verify tool badges and web links render cleanly in the UI.

### Task 5: Progress Tracking
- **Description**:
  - Update `PROGRESS.md` marking Module 7 completed.

## Status: ✅ Completed

### Implementation Summary
1. **Text-to-SQL Service & Tabular Ingestion (`backend/app/services/tools/text_to_sql.py`)**:
   - In-memory shared SQLite database maintaining `documents` and `document_chunks`.
   - Dynamic tabular ingestion for `.csv` files: auto-creates typed SQL tables upon document upload and sanitizes headers.
   - LLM-powered prompt translating natural language questions into safe `SELECT`/`WITH` queries.
   - Strict query validation blocking dangerous mutation statements (`DROP`, `DELETE`, `UPDATE`, `INSERT`, etc.).
   - Results formatted as clean Markdown tables and injected into LLM context.

2. **Zero-Config Web Search Fallback (`backend/app/services/tools/web_search.py`)**:
   - DuckDuckGo HTML web search parser + Instant Answers API fallback using `httpx`.
   - Requires zero external paid API keys.
   - Automatically cleans DuckDuckGo redirects to provide canonical destination URLs, titles, and snippets.

3. **Multi-Tool Router & Agent Orchestration (`backend/app/services/tools/router.py`)**:
   - Detects user intent (`is_sql_intent`, `is_web_explicit`).
   - Automatically executes relevant tools (`local_retrieval`, `text_to_sql`, `web_search`).
   - Fallback policy triggers web search if local document similarity returns 0 results or query asks for live/current events.
   - Streams real-time `tool_events` and unified citations over SSE in `/api/chat/stream`.

4. **Frontend UI Enhancements**:
   - Added tool activation badges in `ChatMessage.tsx` (`📊 Text-to-SQL`, `🌐 Web Search`, `✨ Knowledge Base`).
   - Rendered clickable external links with globe icons in citation drawers.
   - Tool capabilities indicator displayed in `ChatInput.tsx`.
